## 2026-11-21 · M0 · Оркестрация dev/build для Electron+Vite
- Варианты: (а) electron-vite; (б) вручную: vite + tsc для main/preload + concurrently + wait-on.
- Выбрано: (а) electron-vite 6.0.0.
- Причина: один хорошо поддерживаемый пакет вместо трёх (concurrently, wait-on, cross-env) плюс
  готовая корректная сборка main/preload/renderer и dev-режим с запуском Electron. Меньше кода и
  зависимостей — требование ТЗ «минимум зависимостей». Альтернатива «своими руками» — больше
  кода и типовых ошибок (CJS/ESM preload, внешние зависимости main).

## 2026-11-21 · M0 · Версии пакетов
- Зафиксированы точные версии без `^`/`~` (ТЗ §0). Стек: electron 45.4.1, electron-vite 6.0.0,
  vite 8.3.8, @vitejs/plugin-react 6.3.0, react/react-dom 19.3.1, typescript 7.0.2 (tsgo),
  vitest 5.1.1. Все peerDependencies совместимы (проверены по реестру npm).
- electron postinstall скачивает бинарник — разрешён ТЗ явно («postinstall только для известных
  пакетов (electron, esbuild)»).
- electron-builder намеренно НЕ установлен: он нужен только на M5 (минимум зависимостей на этап).

## 2026-11-21 · M0 · CSP в dev-режиме
- Вопрос: строгий `script-src 'self'` ломает dev: @vitejs/plugin-react инжектит inline-прелюд
  Fast Refresh, а meta-CSP нельзя ослабить HTTP-заголовком (политики пересекаются).
- Варианты: (а) ослаблять CSP только в dev плагином transformIndexHtml; (б) 'unsafe-inline'
  всегда; (в) отключить Fast Refresh.
- Выбрано: (а). В dev к script-src добавляется 'unsafe-inline'; prod-бандл выходит строгим
  (проверяется грепом out/renderer/index.html). 'unsafe-inline' для style-src оставлен всегда —
  его требует оверлей ошибок React, пример директив в ТЗ это допускает.

## 2026-11-21 · M0 · Каталог данных в разработке
- По ТЗ §0: в dev данные лежат в каталоге проекта — выбран `.data/` (в .gitignore);

## 2026-11-21 · M0 · Глобальный store UI
- На M0 общего UI-состояния нет (локальный state компонента-заглушки). Единый store вводится на
  M2 вместе с календарём; выбор между Zustand и reducer фиксируется тогда же (ТЗ §5 допускает
  оба). Не считаем это долгом: store — обёртка над одним источником истины, добавляется за один
  коммит.

## 2026-11-21 · M0 · Browser-режим dev
- `npm run dev:browser` — обычный vite с тонким vite.browser.config.ts (тот же корень
  src/renderer, те же плагины). Альтернатива — запуск renderer из electron.vite.config, но
  electron-vite всегда поднимает и Electron. Отдельный конфиг — 12 строк без дублирования
  логики приложения.

## 2026-11-21 · M0 · frame-ancestors в CSP
- Вопрос: пример директив в ТЗ содержит `frame-ancestors 'none'`, но в `<meta>` Chromium
  игнорирует эту директиву и печатает ошибку в консоль — против критерия M0 «нет ошибок,
  связанных с безопасностью».
- Варианты: (а) оставить в meta с фоновым шумом; (б) убрать из meta, при необходимости задать
  HTTP-заголовком (в этом приложении окно грузится локально и iframe-встраивание исключено
  архитектурно — заголовок не нужен вовсе).
- Выбрано: (б). frame-ancestors убрана из meta-CSP; фрейм-защита обеспечивается отсутствием
  удалённого контента и webview.

## 2026-11-21 · M0 · Конфиги vite/vitest как .mts
- Vite 8 анонсировал native-загрузчик конфигов (ESM-синтаксис в .ts, загружаемом как CJS, даёт
  предупреждение). vite.browser.config и vitest.config переименованы в .mts; electron.vite.config.ts
  загружает сам electron-vite — предупреждений нет.
